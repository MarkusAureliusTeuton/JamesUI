# JamesUI 1.0 – Block 7 Icon Library and Asset Registry Design

_Status: design specification for user review_
_Date: 2026-10-03_

## 1. Purpose

Block 7 establishes one permanent icon/asset contract for the new JamesUI 1.0 runtime.

The goal is not to build a large general-purpose icon package. JamesUI needs a small, curated, locally owned icon family that is visually consistent, offline-safe, easy to extend, and independent from Home Assistant internals or external runtime libraries.

Block 7 is infrastructure for later layout/widget blocks. It must not pull forward the Block-8 Start layout, weather/calendar/house providers, page-specific presentation, or the production cutover.

## 2. Binding design decisions

The user selected the hybrid approach (Variant C):

- use an established line-icon family as the stylistic/source baseline;
- vendor only icons JamesUI actually needs;
- create JamesUI-specific icons where the baseline family has no suitable symbol;
- expose all icons through one JamesUI-owned stable registry contract;
- do not create a runtime dependency on the source library.

Tabler Icons is the baseline source/style family.

JamesUI's normalized icon geometry is:

```text
canvas:        24 × 24
stroke width:  2.0 px
fill:          none
stroke:        currentColor
line cap:      round
line join:     round
```

These rules also apply to JamesUI-specific icons so that original and adapted icons are visually indistinguishable as one family.

Tabler is only a source/design reference. Once an icon is imported into JamesUI, its checked-in representation is pinned and changes only through an explicit JamesUI code change. Updating Tabler must never silently alter JamesUI.

## 3. Architectural boundary

The new icon system is a Core-level cross-application service, consistent with the approved JamesUI 1.0 foundation architecture.

Recommended new boundary:

```text
custom_components/jamesui/frontend/icons/
  icon-registry.js
  icon-definitions.js
  icon.js
  ICONS_LICENSE.md
```

The exact implementation-plan file split may be refined without changing this architecture, but responsibilities stay separate:

- **definitions** own normalized vector geometry and provenance metadata;
- **registry** owns stable JamesUI IDs and lookup/validation;
- **icon factory** owns creation of DOM SVG nodes from a registry entry;
- **license/provenance document** records the source/library version and MIT attribution for vendored Tabler-derived icons.

The icon boundary must not depend on:

- Home Assistant state or services;
- Config Service;
- Capability Registry;
- Action Registry;
- page/widget-specific business logic;
- network/CDN access;
- npm runtime packages;
- icon fonts.

## 5. Definition format

JamesUI does not use arbitrary SVG strings at runtime.

Each icon is represented as normalized vector data with a small allowed element vocabulary. The implementation may represent paths as frozen data objects/arrays, but the public contract must not expose raw HTML strings.

Allowed drawing primitives for Block 7:

- `path`
- `line`
- `polyline`
- `circle`
- `rect`

Definitions may contain only geometry attributes needed by those primitives. They may not include:

- scripts;
- event handlers;
- `style` blocks;
- `foreignObject`;
- external references;
- URLs;
- masks/filters unless a later explicit design change proves they are required;
- hard-coded colors;
- arbitrary class names;
- runtime IDs.

The outer SVG styling is owned by the icon factory, not by individual definitions.

## 6. Runtime API

The stable consumer API is intentionally small.

Conceptually:

```js
hasIcon("home.light")
getIconDefinition("home.light")
createIcon(document, "home.light", {
  size: "md",
  label: null,
})
```

`createIcon()` returns a real SVG DOM node.

Default SVG contract:

```text
viewBox="0 0 24 24"
fill="none"
stroke="currentColor"
stroke-width="2"
stroke-linecap="round"
stroke-linejoin="round"
aria-hidden="true"
focusable="false"
```

The consumer controls color through normal CSS `color`; the icon does not accept arbitrary embedded colors.

## 7. Sizes and Design System integration

Block 6 already owns the shared sizes:

```text
sm    → --jui-icon-sm   → 16px
md    → --jui-icon-md   → 20px
lg    → --jui-icon-lg   → 24px
xl    → --jui-icon-xl   → 32px
hero  → --jui-icon-hero → 48px
```

`createIcon()` accepts only these semantic size names. It applies the corresponding token through CSS/data hooks; it does not duplicate pixel constants.

The icon subsystem does not receive the Design System as a service. It relies on the same root-scoped `--jui-*` CSS contract already established in Block 6.

## 8. Accessibility contract

Icons are decorative by default:

```text
aria-hidden="true"
focusable="false"
```

For an icon that carries meaning without adjacent readable text, the caller must pass a non-empty accessible label. In that case the factory produces an SVG with an explicit accessible name and does not mark it hidden.

Normal buttons should continue to get their accessible name from the button label/`aria-label`, not from duplicating the label on the child icon.

The registry must not use visually ambiguous glyphs that differ only through tiny details where a clearer symbol can be provided.

## 9. Source and provenance rules

Vendored standard icons may be derived from Tabler Icons under its MIT license.

For every Tabler-derived definition, JamesUI records provenance metadata such as:

```text
source: tabler
source_name: home
source_version: <pinned imported version>
```

JamesUI-specific drawings use:

```text
source: jamesui
```

The repository contains an `ICONS_LICENSE.md`/equivalent attribution file with the relevant Tabler MIT notice and a short explanation of the vendoring model.

Source metadata is documentation/build-time information. Widgets do not branch on provenance.

## 11. Relationship to legacy assets

Existing files under:

```text
custom_components/jamesui/frontend/assets/weather/
custom_components/jamesui/frontend/assets/alpine/
```

are not part of the new icon family.

The current weather SVGs are large 1600×900 illustration/background assets and must not be normalized or reused as 24×24 UI icons.

They remain untouched until their later weather/asset migration or legacy-deletion blocks decide their fate.

Likewise, r11 Unicode pictograms and inline/data-URL SVG approaches are not migrated into the new registry.

## 12. Consumer integration in Block 7

Block 7 should prove the contract through the persistent Core navigation only.

The five existing navigation buttons may receive the corresponding new icons while preserving:

- current route behavior;
- button labels;
- accessibility;
- persistent navigation identity;
- the Block-6 shared Button primitive.

This is contract integration, not a visual redesign of navigation geometry.

No weather widget, Start hero, House Quick or other Block-8+ UI is implemented in Block 7.

## 13. Error handling

Unknown icon IDs must fail predictably.

Recommended behavior:

- `hasIcon(id)` returns `false`;
- `getIconDefinition(id)` returns `null` for an unknown but syntactically valid ID;
- `createIcon(...)` throws a descriptive error for an unknown/malformed ID rather than silently rendering a random fallback icon.

A visible fallback glyph is deliberately not part of Block 7 because it can hide missing-registry bugs and create inconsistent production UI.

Malformed registry definitions are programmer errors and should be caught by tests/validation before merge.

## 14. Testing and architecture gates

Block 7 must add automated tests for:

- unique stable IDs;
- ID naming rules;
- normalized 24×24 geometry;
- exactly 2.0 px runtime stroke contract;
- `currentColor`/no hard-coded colors;
- allowed SVG primitives/attributes only;
- no URLs, scripts, event attributes, data URLs or external references;
- frozen/immutable registry data;
- semantic size mapping to existing Block-6 tokens;
- decorative vs labelled accessibility behavior;
- unknown-ID behavior;
- provenance metadata for vendored icons;
- navigation integration without changing route behavior;
- no direct Home Assistant/config/capability/action dependency;
- no runtime Tabler package/CDN dependency;
- production `jamesui-entry.js` remains on r11.

The architecture guard should ensure normal new-runtime UI does not reintroduce production Unicode pictograms or ad-hoc inline/data-URL icons after the relevant consumers migrate. Block 7 itself should at minimum guard the new icon boundary and the updated new-Core navigation.

## 15. Explicit non-goals

Block 7 does not:

- implement Block-8 Start layout;
- implement weather/calendar/house providers or widgets;
- migrate all r11 icon usages;
- delete legacy weather illustrations;
- add icon selection UI/configuration screens;
- add an external icon package at runtime;
- add an SVG sprite fetched over the network;
- change the config schema;
- change module contexts;
- change the HA Adapter;
- cut over `jamesui-entry.js` to the new Core.

## 16. Exit criteria

Block 7 is complete when:

- JamesUI owns one stable semantic icon registry;
- the initial roadmap icon set is locally available through stable IDs;
- all icons follow the 24×24 / 2.0 px / `currentColor` line contract;
- Tabler-derived and JamesUI-specific icons are indistinguishable at the contract level;
- provenance/license requirements are checked into the repository;
- consumers can create accessible SVG DOM nodes without knowing source filenames;
- the persistent new-Core navigation uses the registry without changing routing behavior;
- there is no runtime icon-library/CDN dependency;
- no page/domain work from later blocks is pulled forward;
- r11 remains production/reference;
- complete branch and merged-main CI are green.
