# JamesUI 1.0 Block 1 Core Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the new minimal JamesUI Core shell in parallel with r11: stable routes, persistent bottom navigation, raw Home Assistant host-context handoff, technical event/overlay/health services, page error isolation and a mountable Core entry that has no page-specific business logic.

**Architecture:** The new Core lives only under `custom_components/jamesui/frontend/core/` and is not wired into the current Home Assistant production entry during Block 1. `core/index.js` composes small infrastructure services and a structural app shell; r11 remains the production/reference runtime until the later controlled cutover. The Core receives `hass`, `narrow`, `route` and `panel` as opaque host context, but does not inspect Home Assistant state or execute Home Assistant calls; the dedicated HA Adapter remains Block 4.

**Tech Stack:** Browser JavaScript ES modules, standard DOM APIs, Node.js built-in test runner, Python `unittest`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-02-jamesui-1.0-foundation-design.md`

**Baseline:** `docs/JAMESUI_1_0_BASELINE.md`

## Global Constraints

- Variant B only: JamesUI 1.0 is built in parallel while r11 remains the production/reference runtime until the controlled cutover.
- Block 1 must not switch `jamesui-entry.js`, `PANEL_ELEMENT`, `FRONTEND_FILE`, `FRONTEND_REVISION` or any Home Assistant panel registration to the new Core.
- Do not modify the existing legacy runtime files `jamesui-panel.js`, `jamesui-home-entry.js`, `jamesui-home.js`, `jamesui-home-data.js`, `jamesui-home-background.js` or `jamesui-v11-polish.js` in this block.
- Do not implement the Module Registry/Loader from Block 2, Capability/Action Registries from Block 3, HA Adapter from Block 4, structured Config Store from Block 5, Design System from Block 6 or Icon Registry from Block 7.
- The Core may receive raw Home Assistant host values but must not read `hass.states`, registries, WebSocket APIs or services. No `callService`, `callWS`, `sendMessagePromise` or equivalent direct HA access belongs in `frontend/core/`.
- Event Bus use is limited to transient Core/UI/lifecycle/diagnostic events. It is not a data store or action channel.
- Core contains no weather, calendar, house aggregation, Media routing, climate-room or doorbell business logic.
- No runtime monkey-patching, `Panel.prototype` override, foreign render wrapping, release-polish module, version-named production path or permanent compatibility shim.
- Fixed navigation remains `Start | Haus | Klima | Medien | Tür` with route IDs `home | house | climate | media | door`.
- OnePlus Pad 2 portrait remains the primary product target; Block 1 adds structural layout only and must not create a competing visual design system before Block 6.
- No fake Home Assistant data.
- TDD for behavior changes; intentionally red tests never go to `main`.
- Keep `PROJECT_STATUS.md`, `docs/JAMESUI_1_0_EXECUTION_ROADMAP.md` and `docs/JAMESUI_1_0_NEXT_CHAT.md` current when the block is completed.

## Review Focus

1. **Unknown or repeated route requests:** must not corrupt route state or emit duplicate route changes; pinned in Task 1.
2. **One technical event listener throws:** other listeners must still receive the event and the failure must be observable through the supplied error hook; pinned in Task 2.
3. **Overlay replacement/close sequencing:** a stale close callback must not close a newer overlay; pinned in Task 2 and shell behavior in Task 3.
4. **Page renderer throws:** only the page region may fail; persistent navigation must remain usable and recovery on another route must clear stale page-health state; pinned in Task 3.
5. **Pre-mount HA properties plus destroy/remount:** opaque host context assigned before mount must reach the page renderer without raw HA access, and remounting must not duplicate navigation listeners; pinned in Task 4.

### Task 2: Technical event, overlay and health services

**Files:**
- Create: `custom_components/jamesui/frontend/core/event-bus.js`
- Create: `custom_components/jamesui/frontend/core/overlay-service.js`
- Create: `custom_components/jamesui/frontend/core/health-service.js`
- Create: `tests/jamesui-core-services.test.js`

**Interfaces:**
- `createEventBus({ onError = null } = {})` returns `on(type, listener)`, `emit(type, detail)`, `clear()`.
- `on()` returns an unsubscribe function. `emit()` invokes every current listener for that exact event type. A listener exception is forwarded to `onError({ type, error })` and must not stop other listeners.
- `createOverlayService()` maintains one active descriptor. It exposes `current`, `open(descriptor) -> closeCallback`, `close(id = null) -> boolean`, `subscribe(listener) -> unsubscribe`, `clear()`.
- Every overlay descriptor requires a non-empty string `id`; other descriptor fields remain opaque to the service.
- Opening a new overlay replaces the previous one. A close callback returned for an older overlay closes only that overlay ID and therefore must not close a newer overlay.
- `createHealthService()` exposes `report(id, { status, message = "", error = null })`, `get(id)`, `list()`, `clear(id)`, `clearAll()`, `subscribe(listener)`.
- Health records are keyed by ID: a second report for one ID replaces its record rather than creating duplicates.

### Task 3: Structural app shell, persistent navigation and page error isolation

**Files:**
- Create: `tests/helpers/fake-dom.js`
- Create: `custom_components/jamesui/frontend/core/shell.js`
- Create: `tests/jamesui-core-shell.test.js`

**Interfaces:**
- `createAppShell({ document, router, overlays, health, getContext, renderPage } = {})` returns `mount(target)` and `destroy()`.
- `document`, `router`, `overlays`, `health` and `getContext` are required dependencies; `renderPage` is optional.
- The default renderer creates a neutral placeholder for the selected route only. It contains no domain data and performs no Home Assistant access.
- Custom `renderPage({ document, route, context })` returns one DOM node for the page region; tests use injection to prove error isolation and host-context delivery later.
- Shell owns one persistent page region, one bottom navigation, one overlay root and one health surface.
- Shell route changes replace only page-region contents. Bottom navigation node identity must remain stable.
- Navigation buttons use the canonical `CORE_ROUTES` order/labels and call `router.navigate(id)`.
- Structural layout only: shell uses viewport-height/grid structure; bottom navigation is pinned structurally to the bottom (`position: sticky; bottom: 0`) without introducing the future palette/type/icon design system.
- A page render exception is caught, recorded as health ID `page:<routeId>` with status `error`, and replaced with a small neutral page-error node. Navigation remains mounted.
- Leaving the failed route clears that route's page-health record. A later successful render clears the active route error.
- Overlay root reflects `overlays.current`; it must not rebuild or replace the navigation/page shell.

- Create: `tests/test_core_architecture.py`

**Interfaces:**
- `createHostContext({ events } = {})` starts with `{ hass: null, narrow: null, route: null, panel: null }`.
- Host context exposes `set(key, value) -> boolean`, `get(key)`, `snapshot()`.
- Only the exact keys `hass`, `narrow`, `route`, `panel` are accepted. Setting the same value again returns `false`; a real change returns `true` and emits transient event `core:host-context-changed` with `{ key }` only. Raw HA objects are not put on the Event Bus payload.
- `createJamesUICore({ document = globalThis.document, renderPage } = {})` composes router, Event Bus, Overlay Service, Health Service, Host Context and App Shell.
- Returned Core exposes `mount(target)`, `destroy()`, `navigate(routeId)`, read-only service references `router`, `events`, `overlays`, `health`, and `getHostContext()` returning a snapshot.
- Returned Core exposes getters/setters named exactly `hass`, `narrow`, `route`, `panel`; setters delegate to Host Context so a later thin HA panel wrapper can preserve the Block-0 property-replay contract.
- Setting Core `route` stores the opaque Home Assistant route object only; it does not select an internal JamesUI route. Internal page changes use `navigate()` / Router.
- Event Bus listener failures composed through Core are reported to Health Service using health ID `core:event-bus` without aborting remaining listeners.
