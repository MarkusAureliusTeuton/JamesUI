# JamesUI 1.0 Block 7 Icon Library and Asset Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one local, immutable JamesUI icon registry and SVG DOM factory, populate the initial 40-icon roadmap set, and prove the contract by integrating icons into the persistent Core navigation without changing routing behavior.

**Architecture:** `frontend/icons/` is a new HA-free infrastructure boundary. Frozen normalized vector data is validated by a semantic registry and rendered with `createElementNS()` into real SVG DOM nodes; consumers use stable JamesUI IDs and semantic Block-6 size names only. Tabler Icons v3.48.0 is a pinned source/style reference for standard icons, while JamesUI-specific icons follow the same 24×24 / 2px / `currentColor` contract; there is no runtime Tabler, CDN, fetch, icon-font, SVG-string, or XML-parser dependency.

**Tech Stack:** Vanilla ES modules, DOM/SVG namespace APIs, Node `node:test`, Python `unittest` architecture guards, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-03-jamesui-1.0-block-7-icon-asset-system-design.md`

## Global Constraints

- Hybrid Variant C is binding: Tabler Icons is the standard source/style baseline; only icons JamesUI actually needs are vendored.
- Pinned Tabler source version: **3.48.0**.
- Normalized geometry: **24×24**, **2.0 px** stroke, `fill="none"`, `stroke="currentColor"`, round line caps and joins.
- Stable consumer IDs use only `nav.*`, `shell.*`, `weather.*`, `home.*`, `moon.*` in Block 7.
- Runtime SVG creation uses `document.createElementNS()`; no SVG/HTML strings, `innerHTML`, `DOMParser`, runtime file fetch, CDN, npm runtime package, icon font, sprite fetch, or data URL.
- Icon color comes only from inherited CSS `color`; vector definitions contain no hard-coded colors.
- Semantic sizes are exactly `sm | md | lg | xl | hero` and map only to the existing Block-6 tokens `--jui-icon-sm|md|lg|xl|hero`.
- Decorative icons are `aria-hidden="true"` and `focusable="false"`; a standalone meaningful icon requires a non-empty accessible label.
- The initial registry contains exactly the 40 IDs listed in Task 2; no unrelated icon pack is imported.
- The five persistent Core navigation buttons use the new registry while keeping visible labels and route behavior.
- Existing `assets/weather/` and `assets/alpine/` are not migrated or modified in Block 7.
- No Block-8 Start layout, provider/widget/domain logic, config-schema change, module-context change, HA Adapter change, or production cutover.
- r11 production files remain untouched; `jamesui-entry.js` continues to load the legacy runtime.

## Review Focus

1. **Malicious/malformed vector definitions:** unknown primitives, event/style/URL attributes, hard-coded color attributes or invalid provenance must be rejected before a registry becomes usable; Task 1 pins these cases.
2. **Mutation after registration:** callers must not be able to mutate IDs, provenance, node lists or geometry through original inputs or returned definitions; Task 1 pins deep immutability.
3. **Runtime misuse:** unknown IDs, unsupported sizes, missing SVG DOM support, and supplied-but-blank accessibility labels must fail predictably rather than render a silent fallback; Task 3 pins these cases.
4. **Navigation regression:** adding decorative SVG children must preserve visible labels, `aria-current`, click routing, persistent nav identity and remount cleanup; Task 4 pins these cases.
5. **Dependency/legacy leakage:** the new icon boundary must not gain HA/config/domain coupling or external/runtime Tabler access, and production r11 bootstrap must remain unchanged; Task 5 pins these cases.

### Task 1: Icon definition validator and immutable registry contract

**Files:**
- Create: `custom_components/jamesui/frontend/icons/icon-registry.js`
- Create: `tests/jamesui-icon-registry.test.js`

**Interfaces:**
- Produces: `ICON_ID_PATTERN` matching `^(nav|shell|weather|home|moon)\.[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Produces: `createIconRegistry(definitions)` returning a frozen object with `hasIcon(id)`, `getIconDefinition(id)`, `listIconIds()`.
- Definition input shape:

```js
{
  id: "home.light",
  source: "tabler" | "jamesui",
  sourceName: "bulb" | null,
  sourceVersion: "3.48.0" | null,
  nodes: [
    { tag: "path", attrs: { d: "..." } }
  ]
}
```

- Allowed node tags: `path`, `line`, `polyline`, `circle`, `rect`.
- Allowed geometry attributes by tag:
  - `path`: `d`
  - `line`: `x1`, `y1`, `x2`, `y2`
  - `polyline`: `points`
  - `circle`: `cx`, `cy`, `r`
  - `rect`: `x`, `y`, `width`, `height`, optional `rx`, `ry`
- Geometry attribute values are finite numbers or non-empty strings only.
- `tabler` definitions require non-empty `sourceName` and `sourceVersion === "3.48.0"`.
- `jamesui` definitions require `sourceName === null` and `sourceVersion === null`.
- Registry lookup returns `null` for an unknown but syntactically valid ID; `hasIcon()` returns `false`.
- Registry creation rejects duplicate IDs, malformed IDs, empty `nodes`, unknown tags/attributes, `on*`, `style`, `class`, `fill`, `stroke`, URLs/external references, invalid provenance, and mutable nested output.

### Task 3: SVG DOM factory, accessibility and semantic sizing

**Files:**
- Create: `custom_components/jamesui/frontend/icons/icon.js`
- Create: `tests/jamesui-icon.test.js`
- Modify: `custom_components/jamesui/frontend/design/base-styles.js`
- Modify: `tests/helpers/fake-dom.js`

**Interfaces:**
- `icon.js` exports:
  - `SVG_NS = "http://www.w3.org/2000/svg"`
  - `ICON_SIZES = Object.freeze(["sm", "md", "lg", "xl", "hero"])`
  - `createIcon(document, id, { size = "md", label = null } = {})`
- `createIcon()` reads only through `getIconDefinition(id)` from Task 2.
- It requires `document.createElementNS` and creates all SVG/child nodes through that API.
- Outer SVG attributes are exactly:
  - `viewBox="0 0 24 24"`
  - `fill="none"`
  - `stroke="currentColor"`
  - `stroke-width="2"`
  - `stroke-linecap="round"`
  - `stroke-linejoin="round"`
  - `data-jui-icon="<semantic id>"`
  - `data-jui-icon-size="<semantic size>"`
  - `focusable="false"`
- Decorative default: `aria-hidden="true"`, no `role`, no `aria-label`.
- Non-null `label` must be a trimmed non-empty string; labelled icon gets `role="img"`, `aria-label="<label>"`, and no `aria-hidden`.
- Unknown ID, malformed ID, unsupported size, missing SVG DOM support, or supplied blank/non-string label throws a descriptive `TypeError`/`Error`; no fallback glyph.
- `base-styles.js` adds only root-scoped rules:
  - `[data-jui-icon]` display/flex behavior;
  - one selector for each `data-jui-icon-size` value mapping width and height to the existing matching `--jui-icon-*` token.
- No pixel size is duplicated in `icon.js` or `base-styles.js`.
- `FakeElement` gains optional `namespaceURI`; `createFakeDocument()` gains `createElementNS(namespace, tagName)` so icon tests exercise the real API shape.
