# JamesUI 1.0 – Block 14 Implementation Plan

_Date: 2026-10-09_  
_Status: plan for user approval, no product implementation started_  
_Spec: `docs/superpowers/specs/2026-10-09-jamesui-1.0-block-14-start-configuration-design.md`_

## Preflight / review findings

Review against the current source found four important implementation contracts:
1. `core/module-loader.js` keys runtimes and health by module ID; multiple widget instances require a real instance-aware lifecycle without breaking singleton provider/action callers.
2. `layout.home-hero-deck` has four fixed slots and a hard-coded two-column deck. Migrate its canonical slot contract to `hero` + `content`; remove obsolete CSS split and update existing layout tests, not a parallel layout engine.
3. `core/shell.js` currently uses `minHeight:100vh`, rows `1fr auto`, a sticky navigation and a synchronous page renderer. A bounded layout needs an explicit measured page region, instance teardown on routing, and no unwanted scroll. Do not put domain handling in Core.
4. `config-service.js` validates only the six top-level sections and uses full atomic `replace`. Add nested domain validation and coherent update orchestration; retain the single HA-backed store, its schema evolution policy and generation protection.

These are planned changes, not already implemented fixes. Existing Block-8 slot tests/consumers must be migrated consciously. Cross-block layout notes currently describe old slots: update them as part of the same change. No old r11 edits.

## Gate 0 – Branch and baseline (no behavior changes)

- Create isolated `feat/jamesui-1-0-block-14-start-configuration` from verified up-to-date `main`.
- Record exact baseline commit and run the existing Node/Python validation gates before changes.
- Inspect module manifests/registry, main Core boot/bootstrap, config backend schemas, widget constructors, Block-13 button code, and existing tests. Record dependencies and affected assertions before writing tests.
- Keep deliberate red TDD tests local to feature development; only green stable checkpoints submitted to GitHub CI.

## Gate 1 – Persistent page/instance/grid model

- Define and test normalized schema for `pages`, `layouts`, `widget_instances` and page element placements inside existing root sections; stable ID/ref rules; `widget` and `button` element kinds; future registry-extensible element kinds.
- Define grid geometry explicitly (zero- vs one-based), integer row/column origin and spans, limits, minimum sizes, ordered presentation semantics, deliberate gaps, and fixed-vs-vertical layout policies.
- Define per-page hero settings with existing validation `0.35 ≤ hero_ratio ≤ 0.50`; fullscreen configuration ignores hero gracefully.
- Add versioned nested validation in frontend/backend appropriately without breaking migrated schema-v1 configs. Unsupported versions, invalid geometry, dangling references or duplicate IDs return specific errors; failed writes never damage last valid configuration.
- Tests: schema roundtrip, migration/defaults, atomic invalid replacement, missing refs, duplicate instance IDs, external concurrent edits/stale completions.

## Gate 2 – Canonical instance-aware module lifecycle

- Evolve existing Module Loader, distinguish module definition ID from runtime instance ID. Existing singleton `load(id)` callers should remain valid via the canonical API; avoid introducing a second loader or long-lived compatibility layer.
- Ensure distinct widget instances use independent `create/mount/update/destroy` calls, configs, target nodes and health identities while sharing provider capabilities.
- Protect concurrent loads/unloads/reloads, route transitions, config rebinding and failed lifecycle phases from stale callbacks/duplicate mounts.
- Tests: two Agenda instances with different sources; two Dynamic Buttons with shared status but independent pending; mount order, destroy isolation, reload semantics, failure reporting and leak regression.

## Gate 3 – Layout composition and measured viewport

- Migrate Block-8 hero/deck layout to fixed hero + free 12-column content deck; preserve visual hero ratio and top overlap. Add minimal fullscreen layout variant through official layout registration only.
- The Shell reserves visible bottom navigation without stealing widget space or causing body scrolling. The visual deck extends under nav; logical interactive grid stops above it. Explicit viewport measurement/resize and a layout-owned `fixed|vertical` scroll decision.
- Implement a single tested shared logical grid mechanism: 12 columns, fixed logical row unit per layout, integer spans and position, minimum bounds, independent widget interior, optional internal overflow.
- Grid row size must be selected using actual viewport and touch/readability criteria; do not set unapproved 16/24/32 px as immutable product decisions.
- Tests: hero ratios, fullscreen, layout resize, null/unavailable devices, no clipped hit targets, fixed page bounds, absence of auto-compaction, no giant recalculation on Agenda content change.

## Gate 4 – First-class button composition

- Refactor the existing Dynamic Buttons rendering/interaction boundary so a single central `dynamic_buttons` definition can be placed as one independent page element.
- Retain all Block-13 behavior: real feedback revision gating, toggle vs trigger, Action Registry, pending/timeout/success/failure, unavailable state and instance-local transient feedback. No duplicate button state machine.
- Retain aggregate widget behavior where existing consumers need it, but no compulsory aggregate for Start composition.
- Tests: action acceptance is not state proof, shared source plus independent interactions, disabled unavailable button, single-element per-page geometry, oversized/min-size behavior.

## Gate 5 – Pure edit-model and collision engine

- Build pure deterministic functions for candidate placements, drag and resize, edge bounds, minimum spans, local collision push and rejection. Avoid silent global compaction. Prefer minimal displacement; preserve unaffected elements and deliberate empty cells.
- On every edit preview produce proposed placements without persisting; commit once on pointer completion. Provide undo using session snapshots and restore on failed save.
- Tests: horizontal/vertical move, multi-element collisions, impossible placement, chains, explicit empty spaces, resizing, orientation/viewport changes, undo, persist/reload determinism.

## Gate 6 – Editor UI, catalogs and settings

- Direct Long-Press enters edit mode; pointer/touch move handles, snap previews, resize grips, context action menu `Konfigurieren | Duplizieren | Entfernen`, and `+ Hinzufügen` catalog.
- Register Weather/Agenda/House Quick/individual Dynamic Buttons with metadata and dependency-aware settings. Each occurrence has own selected sources and display preferences. Future organizational elements can register without replacing the editor framework.
- Commit coherent changes to the existing Config Service; loading and saving feedback, error recovery, no action trigger on release after long-press, `Fertig` ends editing.
- Tests: touch pointer-cancel behavior, keyboard/focus and tap vs long-press arbitration, unsaved error, duplicate/remove, widget instance configuration isolation, editor exit/reentry.

## Gate 7 – First composed Start release candidate

- Compose Weather Today hero, Calendar Agenda, House Quick, and selected individual Dynamic Buttons using real capabilities; no invented data or predetermined button count. Configure a sane first layout only once real CSS viewport and minimum sizes are checked.
- Avoid linking unusable secondary pages to fake route contents. This becomes a formal Block-19 release condition; do not migrate secondary page content in Block 14.
- Validate OnePlus Pad 2 portrait / Fully **visually**: obtain actual CSS viewport/nav dimensions, screenshot and user acceptance of element comfort, open-ended deck, bounded fixed screen, page availability, configuration workflows. Do not claim device acceptance merely from unit tests.

## Gate 8 – Review, verification and merge

- Targeted Node tests and Python unittest followed by full repository validation workflow; architecture checks (no raw HA in widgets, no unregistered action bypass, no parallel loader).
- Whole-branch review: data flow, schema concurrency, subscriptions/cleanup, stale async results, reflow determinism, touch gestures, tablet behavior, accessibility, cross-block regressions. Fix Critical/Important findings with permanent regression tests.
- Last green CI must correspond to unchanged final PR branch head. Merge once approval applies; verify main CI.
- Then and only then update status/roadmap/handover together. Preserve early-cutover execution order: 19–21 precede 15–18.
