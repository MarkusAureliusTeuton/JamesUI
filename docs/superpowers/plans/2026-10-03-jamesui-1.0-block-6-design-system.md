# JamesUI 1.0 Block 6 – Design System and Base Components Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish one root-scoped Alpine-Chic design system with stable CSS design tokens and reusable surface/button/overlay/dialog primitives for all new JamesUI 1.0 UI.

**Architecture:** Keep visual infrastructure in a dedicated `frontend/design/` boundary. One Design System service mounts a single root-scoped style element into the parallel Core shell; all application-wide palette, typography, spacing, radii, shadow/blur, motion and icon-size values come from one frozen token contract. Base primitives expose small DOM factories and semantic `data-jui-*` hooks; later layouts/widgets may add local styles, but must consume shared CSS variables instead of redefining the application palette/type system.

**Tech Stack:** JavaScript ES modules / DOM APIs / CSS custom properties / Node built-in test runner; existing Python `unittest` architecture guards.

**Spec:** `docs/superpowers/specs/2026-10-02-jamesui-1.0-foundation-design.md`

## Global Constraints

- Variant B remains binding: r11 stays production/reference until the controlled cutover.
- OnePlus Pad 2 portrait remains the primary visual target; Fully remains only the kiosk shell.
- Visual direction remains premium Alpine-Chic: near-black/anthracite foundation, restrained warm champagne accent, soft architectural depth, no generic Lovelace/card look and no glowing borders.
- Block 6 introduces no weather/calendar/house/media/climate/door business logic, no Start layout, no dynamic buttons and no production bootstrap cutover.
- Block 7 owns the SVG icon library/asset registry. Block 6 may define icon-size tokens and icon-ready button spacing, but must not add SVG assets, Unicode icon fallbacks, data-URL icons or `url(...)` visual assets.
- No new third-party dependency and no external/custom font download. Use the platform/system font stack.
- The Design System is scoped below the JamesUI Core root and must not modify Home Assistant's global document styles.
- No `!important`, runtime monkey-patching, Prototype overrides, version-specific polish modules or CSS rewrite layers.
- Raw application palette/type values belong only in the central token contract. Primitive/base styles consume `var(--jui-...)` tokens.
- Reduced-motion behavior is centralized through motion tokens; primitives must not hard-code independent animation durations.
- Existing module contexts remain unchanged. Do not add Design System, raw CSS objects or DOM styling services to module context; modules consume CSS variables and may statically import the generic primitive factories where appropriate.
- Existing Overlay Service behavior/descriptor contract is not expanded in Block 6. Overlay/dialog primitives are presentation building blocks for later blocks.
- r11 frontend files and `jamesui-entry.js` remain untouched.

## Review Focus

1. **Repeated mount/remount:** mounting on the same root never duplicates design styles; mounting on a different root cleans the old marker/style before applying the new one; destroy is idempotent.
2. **Reduced motion:** all shared interactive transitions use motion tokens, and `prefers-reduced-motion: reduce` collapses the three duration tokens to `0ms` without requiring `!important`.
3. **Primitive misuse:** unsupported surface/button variants or button sizes fail fast; a button must have visible text or an explicit accessible label.
4. **Visual drift:** raw palette literals, `!important`, `url(...)`, inline SVG/data-URL assets and release-specific selectors are forbidden outside the central token values/legacy r11 files.
5. **Architecture leakage:** Design System introduces no direct Home Assistant access, does not enter module context, and does not alter the production r11 bootstrap.

### Task 2: Root-scoped Design System service and base CSS

**Files:**
- Create: `custom_components/jamesui/frontend/design/base-styles.js`
- Create: `custom_components/jamesui/frontend/design/design-system.js`
- Create: `tests/jamesui-design-system.test.js`

**Interfaces:**
- `base-styles.js` exports `BASE_DESIGN_STYLES`, containing only selectors below `[data-jui-design-root]` plus the reduced-motion media query.
- Base styles define:
  - root dark color-scheme, canvas/text/font defaults and box sizing,
  - generic `[data-jui-surface]` variants `default | raised | glass`,
  - generic `[data-jui-button]` variants `default | ghost | accent` and sizes `sm | md | lg`,
  - focus-visible, disabled, active/current/pressed states,
  - `[data-jui-overlay]`, `[data-jui-dialog]`, `[data-jui-dialog-title]`, `[data-jui-dialog-body]`, `[data-jui-dialog-actions]` presentation.
- All palette, typography, radius, shadow, blur and transition references inside `BASE_DESIGN_STYLES` use `var(--jui-...)`; no `!important` and no `url(...)`.
- `design-system.js` produces `buildDesignStyleText() -> string`, serializing the canonical token object into the `[data-jui-design-root]` rule before `BASE_DESIGN_STYLES`.
- `design-system.js` produces `createDesignSystem({ document })` returning:
  - `mount(root) -> styleElement`
  - `destroy() -> boolean`
- `mount(root)` requires an appendable DOM-like root, adds `data-jui-design-root=""`, and appends one `<style data-jui-design-system="1">` child.
- Re-mount on the same root returns the existing style element without duplication.
- Mount on a different root first removes the old style and root marker.
- `destroy()` removes style + marker once and returns `true`; later calls return `false`.
- The style is mounted inside JamesUI root, never `document.head`, so no Home Assistant global CSS is mutated.

### Task 3: Reusable DOM base primitives

**Files:**
- Create: `custom_components/jamesui/frontend/design/primitives.js`
- Create: `tests/jamesui-design-primitives.test.js`

**Interfaces:**
- Produces frozen value lists:
  - `SURFACE_VARIANTS = ["default", "raised", "glass"]`
  - `BUTTON_VARIANTS = ["default", "ghost", "accent"]`
  - `BUTTON_SIZES = ["sm", "md", "lg"]`
- Produces `createSurface(document, { tagName = "section", variant = "default" } = {}) -> Element`.
  - creates the requested tag and sets `data-jui-surface=<variant>`;
  - rejects unsupported/empty variants and invalid tag names.
- Produces `createButton(document, { label = "", ariaLabel = null, variant = "default", size = "md", type = "button" } = {}) -> Element`.
  - requires a non-empty visible `label` or non-empty `ariaLabel`;
  - defaults to `type="button"`;
  - sets `data-jui-button=<variant>` and `data-jui-button-size=<size>`;
  - sets `aria-label` only when provided;
  - adds no icon implementation and no click listener.
- Produces `createOverlayFrame(document) -> Element`, returning a `div[data-jui-overlay]` presentation container with no service coupling.
- Produces `createDialog(document, { title }) -> Object.freeze({ root, title, body, actions })`.
  - requires non-empty `title`;
  - root is `div[data-jui-dialog]` with `role="dialog"`, `aria-modal="true"` and `aria-label=<title>`;
  - child hooks are `data-jui-dialog-title`, `data-jui-dialog-body`, `data-jui-dialog-actions`;
  - no close behavior is invented; callers/Overlay Service own lifecycle.

- production r11 bootstrap and frontend remain untouched;
