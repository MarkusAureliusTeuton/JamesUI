# JamesUI 1.0 – Block 11 Calendar, Tasks and Agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `provider.calendar`, `provider.tasks`, `action.task-update` and `widget.calendar-agenda` exactly to the approved Block-11 design, with truthful Home Assistant time/source semantics, task completion/editing, JamesUI-owned advance notices and bounded host-aware rendering, while leaving r11 production and final Start composition untouched.

**Architecture:** Calendar is a range-based read capability, tasks are a live normalized snapshot, mutations go through one semantic `task.update` action, and the Agenda widget owns only presentation/transient UI. Providers/actions alone use the Home Assistant Adapter. Small pure shared helpers own zoned-time arithmetic and Todo feature bits so provider/action/widget modules do not duplicate those contracts or add domain behavior to Core.

**Tech Stack:** Vanilla ES modules, existing JamesUI Module/Capability/Action/Overlay contracts, Home Assistant Adapter, Block-6 design tokens/primitives, Block-7 semantic icon registry, Node `node:test`, Python architecture gates, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-04-jamesui-1.0-block-11-calendar-tasks-agenda-design.md`

## Global Constraints

- Primary visual target remains OnePlus Pad 2 portrait; Fully is kiosk shell only.
- r11 remains production/reference. Do not change `jamesui-entry.js` production behavior or perform Start composition/cutover.
- `widget.calendar-agenda` has no raw Home Assistant access and never imports the Home Assistant Adapter.
- Providers/actions use only the existing `context.homeAssistant` adapter; no raw `hass` shortcuts.
- User commands go through the Action Registry. Todo mutation from the widget is only `task.update`, never generic `ha.service`.
- Calendar/task source selection is explicit. No auto-discovery fallback content.
- All Agenda domain date/time semantics use validated Home Assistant timezone metadata. Browser timezone is never a silent fallback.
- Missing/unavailable backend data stays explicit. Do not reuse stale event/task values as current after source failure/disconnect.
- Page scrolling and widget allocation remain layout responsibilities. Agenda may scroll internally but may not grow its host merely to expose more content.
- Generic multi-instance loader/page orchestration stays Block 14. Block 11 proves the widget itself is safe for multiple direct `create()` instances.
- No task create/delete/move/reorder and no calendar mutation in this block.
- No source reminder/alarm claims. Advance notices are explicitly JamesUI-owned.
- No monkey-patches, Prototype overrides, release-polish layers, parallel implementations or permanent compatibility shims.
- TDD is mandatory. Intentionally red tests stay on the implementation branch and never reach `main`.

## Review Focus

1. **Timezone/DST truthfulness:** range boundaries, midnight, multi-day projection, task edits and advance thresholds must remain deterministic across DST without browser-time fallback.
2. **Stale-data isolation:** source removal/unavailability, reconnect, config update and late callbacks must never republish stale event/task data.
3. **Calendar range ownership:** shared range ref-count/unsubscribe races must not disconnect an active sibling consumer.
4. **Todo clearing:** due clear must determine whether the real item currently has date or datetime due; never send both HA due fields.
5. **Optimistic task state:** completion/Undo/edit races must reconcile to capability truth; multiple Undo entries remain independent.
6. **Advance notices:** extended retrieval must not leak events into normal rows; lead calculations use local calendar days, not fixed 24h.
7. **Host sizing:** no partial rows/page-growth/geometry jumps when notices/status/location are present.
8. **Instance isolation:** two direct Agenda instances with different source/mode/dismiss state never share transient state.
