# JamesUI 1.0 – Block 12 House Capabilities and House Quick Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement real, explicitly configured House-domain read capabilities and a reusable `widget.house-quick` that shows heating-zone, lighting, ambient-lighting, household-device and energy status and navigates semantically to later detail pages.

**Architecture:** Four provider modules own all Home Assistant/KNX-backed reads and normalize them into five JamesUI capabilities. `widget.house-quick` consumes only capabilities and the Action Registry; it never receives raw Home Assistant state. Energy uses a provider-owned query/subscription service backed by Home Assistant `history/history_during_period`, while per-button averaging windows and warning/critical thresholds remain widget-instance configuration.

**Tech Stack:** Home Assistant custom integration, browser ES modules, Node.js built-in test runner, Python `unittest` architecture guards, existing JamesUI Core/Capability Registry/Action Registry/Home Assistant Adapter/Design System/Icon Registry.

**Spec:** `docs/superpowers/specs/2026-10-05-jamesui-1.0-block-12-house-capabilities-house-quick-design.md`

## Global Constraints

- Keep r11 as production/reference; do not wire Block 12 into `jamesui-entry.js`, `jamesui-home-entry.js`, `jamesui-home.js` or `jamesui-panel.js`.
- Widgets consume capabilities/actions only; providers may use the Home Assistant Adapter.
- No raw `hass`, Router, Config Service, Health Service, Design System object, Module Registry or Module Loader inside `widget.house-quick`.
- No monkey-patches, Prototype overrides, version-polish layers, duplicate implementations or compatibility shims.
- Runtime source assignment is explicit only; no entity-name heuristics or automatic inclusion of discovered entities.
- Normal light and ambient light assignments are mutually exclusive.
- KNX owns heating-zone grouping and heating-control semantics; JamesUI only normalizes already exposed zone values.
- House Quick status priority is exactly `critical > warning > active > neutral`.
- Unreachable configured sources are `warning`; update availability alone is informational.
- Heating `active` is driven by `auto_regulation_enabled`, never by `heating_demand`.
- Energy threshold evaluation uses the trailing average, not instantaneous power; current power remains the primary displayed value.
- Every House Quick instance owns its own button subset, order, heating-zone subset, energy windows/thresholds and navigation metadata.
- Windows/doors, ventilation, scenes, direct control, detail pages, final Start composition and generic arbitrary instance orchestration are out of scope.
- OnePlus Pad 2 portrait is the primary visual target; page scrolling remains a layout concern.
- Use TDD for behavior changes. Never commit an intentional red test to the shared implementation branch.
- Run full CI only at green checkpoints; use targeted tests during tasks.
- Update project status/roadmap/handover once, only after Block 12 is merged and main CI is green.

## Review Focus

1. **Partial-source failure:** one unavailable signal inside a heating zone/device/light group must create a truthful warning without blanking healthy sibling data.
2. **Sliding energy window with no new HA state event:** the trailing average must refresh as time advances, so an old spike can age out even if the live sensor value does not change.
3. **Stale async energy result after update/destroy:** late history responses must never publish into a replaced provider service or resurrect removed consumers.
4. **Duplicate/overlapping configuration:** normal/ambient lighting overlap, duplicate stable IDs and malformed energy thresholds/windows must be rejected deterministically.
5. **Navigation before detail routes exist:** clicking a valid House Quick button may receive an Action Registry `rejected` result, but must not create hidden global state, throw, or perform fallback raw navigation.
